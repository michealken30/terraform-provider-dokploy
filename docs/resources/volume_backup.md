# dokploy_volume_backup (Resource)

Manages a Dokploy volume backup configuration. This resource backs up Docker volumes to a storage destination on a schedule.

~> **Note:** This is different from `dokploy_backup` which performs database-specific backups (pg_dump, mysqldump, etc.). Volume backups copy the raw Docker volume data and work with any service type.

## Example Usage

```terraform
# Back up application uploads volume
resource "dokploy_volume_backup" "app_uploads" {
  name            = "uploads-backup"
  volume_name     = "myapp-uploads"
  prefix          = "uploads"
  cron_expression = "0 2 * * *" # Daily at 2 AM
  destination_id  = dokploy_destination.s3.id

  application_id = dokploy_application.web.id
  service_type   = "application"

  keep_latest_count = 7
  enabled           = true
}

# Back up Redis persistence volume with service stop
resource "dokploy_volume_backup" "redis_data" {
  name            = "redis-backup"
  volume_name     = "redis-data"
  prefix          = "redis"
  cron_expression = "0 3 * * *" # Daily at 3 AM
  destination_id  = dokploy_destination.s3.id

  redis_id     = dokploy_redis.cache.id
  service_type = "redis"

  # Stop Redis during backup for consistency
  turn_off          = true
  keep_latest_count = 14
  enabled           = true
}

# Back up compose service volume
resource "dokploy_volume_backup" "compose_data" {
  name            = "compose-data-backup"
  volume_name     = "app-data"
  prefix          = "compose-data"
  cron_expression = "0 4 * * 0" # Weekly on Sunday at 4 AM
  destination_id  = dokploy_destination.s3.id

  compose_id   = dokploy_compose.stack.id
  service_type = "compose"
  service_name = "worker" # Specific service in compose stack

  keep_latest_count = 4
  enabled           = true
}
```

## Schema

### Required

- `cron_expression` (String) Cron expression for the backup schedule (e.g., '0 2 * * *' for daily at 2 AM).
- `destination_id` (String) The ID of the storage destination for backups.
- `name` (String) The name of the volume backup configuration.
- `prefix` (String) The prefix for backup files in the destination.
- `volume_name` (String) The name of the Docker volume to back up.

### Optional

- `app_name` (String) The application name (used for identifying the volume).
- `application_id` (String) The application ID if backing up an application volume.
- `compose_id` (String) The compose service ID if backing up a compose volume.
- `enabled` (Boolean) Whether the backup schedule is enabled.
- `keep_latest_count` (Number) Number of recent backups to keep. Older backups are automatically deleted.
- `mariadb_id` (String) The MariaDB service ID if backing up a MariaDB volume.
- `mongo_id` (String) The MongoDB service ID if backing up a MongoDB volume.
- `mysql_id` (String) The MySQL service ID if backing up a MySQL volume.
- `postgres_id` (String) The PostgreSQL service ID if backing up a PostgreSQL volume.
- `redis_id` (String) The Redis service ID if backing up a Redis volume.
- `service_name` (String) The service name within a compose stack.
- `service_type` (String) The type of service owning the volume. Valid values: 'application', 'postgres', 'mysql', 'mariadb', 'mongo', 'redis', 'compose'.
- `turn_off` (Boolean) Whether to stop the service during backup for consistency.

### Read-Only

- `id` (String) The unique identifier of the volume backup.

## Import

Volume backups can be imported using their ID:

```shell
terraform import dokploy_volume_backup.example abc123-volume-backup-id
```

Or using import blocks (Terraform 1.5+):

```hcl
import {
  to = dokploy_volume_backup.example
  id = "abc123-volume-backup-id"
}
```
