# dokploy_mysql (Resource)

Manages a Dokploy MySQL database service within an environment.

## Example Usage

```terraform
# Create a MySQL database

resource "dokploy_project" "example" {
  name = "my-project"
}

resource "dokploy_environment" "prod" {
  project_id = dokploy_project.example.id
  name       = "prod"
}

resource "dokploy_mysql" "main" {
  environment_id = dokploy_environment.prod.id
  name           = "mysql-db"
  description    = "MySQL database"
  database_name  = "myapp"
  database_user  = "appuser"
  docker_image   = "mysql:8.0"
}

output "mysql_id" {
  value = dokploy_mysql.main.id
}
```

## Schema

### Required

- `environment_id` (String) The ID of the environment this database belongs to.
- `name` (String) The name of the mysql database.

### Optional

- `database_name` (String) The name of the database to create.
- `database_password` (String, Sensitive) The database password.
- `database_root_password` (String, Sensitive) The database root password.
- `database_user` (String) The database user.
- `description` (String) The description of the mysql database.
- `docker_image` (String) The Docker image to use (e.g., mysql:8).
- `server_id` (String) The ID of the server to deploy to (optional, uses default if not specified).

### Read-Only

- `app_name` (String) The internal app name (used for container naming). Computed by Dokploy.
- `id` (String) The unique identifier of the mysql database.

## Import

MySQL databases can be imported using their ID:

```shell
terraform import dokploy_mysql.example pqr678-mysql-id
```

Or using import blocks (Terraform 1.5+):

```hcl
import {
  to = dokploy_mysql.example
  id = "pqr678-mysql-id"
}
```

### Finding MySQL IDs

Use the `dokploy_environments` data source to discover MySQL IDs within environments:

```hcl
data "dokploy_environments" "all" {
  project_id = dokploy_project.example.id
}

output "mysql_ids" {
  value = flatten([
    for env in data.dokploy_environments.all.environments : [
      for m in env.mysql : {
        environment = env.name
        name        = m.name
        id          = m.id
      }
    ]
  ])
}
```

~> **Note:** Sensitive values like `database_password` and `database_root_password` will not be populated during import. You will need to set these values in your configuration after import.
