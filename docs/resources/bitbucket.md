# dokploy_bitbucket (Resource)

Manages a Dokploy Bitbucket provider integration. Allows connecting to Bitbucket Cloud for source code access.

## Example Usage

```terraform
# Bitbucket provider with app password
resource "dokploy_bitbucket" "main" {
  name    = "company-bitbucket"
  auth_id = "user-auth-id"

  bitbucket_username       = "my-username"
  bitbucket_email          = "user@example.com"
  app_password             = var.bitbucket_app_password
  bitbucket_workspace_name = "my-workspace"
}

# Bitbucket with API token
resource "dokploy_bitbucket" "api_token" {
  name    = "bitbucket-api"
  auth_id = "user-auth-id"

  bitbucket_username = "my-username"
  api_token          = var.bitbucket_api_token
}
```

## Schema

### Required

- `auth_id` (String) The authentication ID for the provider.
- `name` (String) The name of the Bitbucket provider.

### Optional

- `api_token` (String, Sensitive) The Bitbucket API token.
- `app_password` (String, Sensitive) The Bitbucket app password for authentication.
- `bitbucket_email` (String) The Bitbucket account email.
- `bitbucket_username` (String) The Bitbucket username.
- `bitbucket_workspace_name` (String) The Bitbucket workspace name to restrict repository access.
- `organization_id` (String) The organization ID to associate this provider with.

### Read-Only

- `git_provider_id` (String) The git provider identifier used for deletion.
- `id` (String) The unique identifier of the Bitbucket provider (bitbucketId).

## Import

Bitbucket providers can be imported using their Bitbucket ID:

```shell
terraform import dokploy_bitbucket.example abc123-bitbucket-id
```

Or using import blocks (Terraform 1.5+):

```hcl
import {
  to = dokploy_bitbucket.example
  id = "abc123-bitbucket-id"
}
```

~> **Note:** Sensitive fields like `app_password` and `api_token` will not be readable after import. You will need to set these values in your configuration after import.
