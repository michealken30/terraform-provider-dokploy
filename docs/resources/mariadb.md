# dokploy_mariadb (Resource)

Manages a Dokploy MariaDB database service within an environment.

## Example Usage

```terraform
# Create a MariaDB database

resource "dokploy_project" "example" {
  name = "my-project"
}

resource "dokploy_environment" "prod" {
  project_id = dokploy_project.example.id
  name       = "prod"
}

resource "dokploy_mariadb" "main" {
  environment_id = dokploy_environment.prod.id
  name           = "mariadb"
  description    = "MariaDB database"
  database_name  = "wordpress"
  database_user  = "wp_user"
  docker_image   = "mariadb:11"
}

output "mariadb_id" {
  value = dokploy_mariadb.main.id
}
```

### Required

- `name` (String) The name of the mariadb database.

### Optional

- `database_name` (String) The name of the database to create.
- `database_password` (String, Sensitive) The database password.

- `database_user` (String) The database user.
- `description` (String) The description of the mariadb database.
- `docker_image` (String) The Docker image to use (e.g., mariadb:11).

- `id` (String) The unique identifier of the mariadb database.

## Import

MariaDB databases can be imported using their ID:

```shell
terraform import dokploy_mariadb.example stu901-mariadb-id
```

Or using import blocks (Terraform 1.5+):

```hcl
import {
  to = dokploy_mariadb.example
  id = "stu901-mariadb-id"
}
```

### Finding MariaDB IDs

Use the `dokploy_environments` data source to discover MariaDB IDs within environments:

```hcl
data "dokploy_environments" "all" {
  project_id = dokploy_project.example.id
}

output "mariadb_ids" {
  value = flatten([
    for env in data.dokploy_environments.all.environments : [
      for m in env.mariadb : {
        environment = env.name
        name        = m.name
        id          = m.id
      }
    ]
  ])
}
```

~> **Note:** Sensitive values like `database_password` and `database_root_password` will not be populated during import. You will need to set these values in your configuration after import.
