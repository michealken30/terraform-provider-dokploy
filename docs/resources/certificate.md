# dokploy_certificate (Resource)

Manages a Dokploy SSL certificate. Certificates are used for HTTPS on custom domains.

## Example Usage

```terraform
# Upload an SSL certificate

resource "dokploy_certificate" "wildcard" {
  name             = "wildcard-cert"
  certificate_data = file("certs/fullchain.pem")
  private_key      = file("certs/privkey.pem")
  auto_renew       = false
  organization_id  = var.organization_id
}

variable "organization_id" {
  description = "Dokploy organization ID"
  type        = string
}

output "certificate_id" {
  value = dokploy_certificate.wildcard.id
}
```

## Schema

### Required

- `certificate_data` (String, Sensitive) The certificate data (PEM format).
- `name` (String) The name of the certificate.
- `organization_id` (String) The organization ID this certificate belongs to.
- `private_key` (String, Sensitive) The private key for the certificate (PEM format).

### Optional

- `auto_renew` (Boolean) Whether to auto-renew the certificate.

### Read-Only

- `certificate_path` (String) The path where the certificate is stored. Computed by Dokploy.
- `id` (String) The unique identifier of the certificate.

## Import

Certificates can be imported using their ID:

```shell
terraform import dokploy_certificate.example klm789-certificate-id
```

Or using import blocks (Terraform 1.5+):

```hcl
import {
  to = dokploy_certificate.example
  id = "klm789-certificate-id"
}
```

### Finding Certificate IDs

Use the `dokploy_certificates` data source to discover certificate IDs:

```hcl
data "dokploy_certificates" "all" {}

output "certificate_ids" {
  value = { for c in data.dokploy_certificates.all.certificates : c.name => c.id }
}
```

~> **Note:** The `private_key` value will not be populated during import. You will need to set this value in your configuration after import.
